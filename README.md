# SVN Workspace

체크아웃, 업데이트, 선택 항목 커밋, 커밋 이력 확인에 집중한 개인용 macOS SVN 앱입니다. 밝은 좌우 분할 화면에서 왼쪽은 커밋 목록, 오른쪽은 메시지·변경 파일·텍스트 diff를 보여줍니다.

현재 버전은 **0.1.3 MVP**입니다. Electron + React + TypeScript로 만들었으며, 맥에 설치된 `svn` 명령을 호출합니다. 별도 앱 계정이나 중계 서버는 사용하지 않습니다.

## 0.1.3 변경 사항

- 삭제된 폴더와 로컬에서 통째로 지워 누락된 폴더를 선택해 커밋할 수 있습니다.
- 삭제 폴더를 누르면 함께 삭제될 하위 파일·폴더 목록과 개수를 보여줍니다. 목록의 파일을 누르면 삭제되는 내용을 확인할 수 있습니다.
- 폴더가 포함된 커밋은 최신 삭제 목록을 조회한 뒤 **폴더 삭제 범위 확인 → 삭제 포함 커밋**으로 진행합니다. 조회 실패 시 커밋을 진행하지 않습니다.
- 하위 삭제는 상위 폴더와 중복 선택되지 않으며 다른 미선택 파일의 변경은 커밋에 포함하지 않습니다. 폴더의 신규 추가·속성 변경을 직접 선택하는 기능은 계속 지원하지 않습니다.

## 0.1.2 변경 사항

- 상단 **VS Code** 버튼으로 선택한 프로젝트의 실제 폴더를 새 VS Code 창에서 엽니다. 설치된 `code` 명령을 자동으로 찾으며, 실행 파일이나 대상 폴더를 찾지 못하면 안내합니다.
- 프로젝트 선택창 옆 **⋯ → 별칭 변경**에서 앱에 표시할 이름을 저장합니다. 목록에는 `별칭 (원래 폴더명)`이 표시되며 전체 경로는 마우스를 올려 확인할 수 있습니다.
- 별칭은 이 앱의 설정에만 저장됩니다. 폴더명, SVN URL, 작업 파일은 바꾸지 않습니다. **폴더명으로 초기화 → 저장**으로 기본 이름으로 돌아갈 수 있습니다.
- 설정·별칭·VS Code 실행 도우미 테스트 10개와 가상 API를 사용하는 Electron 화면 회귀 검증을 통과했습니다. 실제 업무 프로젝트를 VS Code로 여는 실행은 검증 과정에서 하지 않았습니다.

## 0.1.1 변경 사항

- 커밋 목록 오른쪽 경계를 드래그해 너비를 조절할 수 있습니다. 폭은 앱에 저장되며 창이 작아지면 상세 영역을 확보하도록 조정됩니다. 경계에 초점을 두고 방향키로도 조절할 수 있습니다.
- 프로젝트 전환 직후 새 프로젝트에 이전 프로젝트의 리비전·파일 경로로 diff를 요청하던 문제를 수정했습니다. 이전 요청의 늦은 오류 응답도 현재 화면에 표시하지 않습니다.
- 두 가상 프로젝트를 사용한 실제 Electron 회귀 검증에서 오류를 재현한 뒤 수정 결과를 확인했습니다. 이 검증은 SVN 실행이나 실제 저장소 접근 없이 동작합니다.

## 준비 사항

- macOS와 별도로 설치한 Subversion CLI가 필요합니다. SVN 실행 파일은 앱에 포함하지 않습니다. 통합 테스트에서는 SVN 1.14.5를 사용했습니다.
- 개발 실행에는 Node.js 22.12 이상과 npm을 사용하세요.
- 기존 SVN 저장소 URL과 필요한 경우 해당 저장소 계정이 필요합니다.

앱은 저장된 SVN 경로 또는 `/opt/homebrew/bin/svn`, `/usr/local/bin/svn`, `/usr/bin/svn`, `PATH` 순서로 실행 파일을 찾습니다. 찾지 못하면 시작 화면의 **SVN 실행 파일 선택**으로 직접 지정합니다. 저장된 경로가 더 이상 유효하지 않을 때도 실행 파일을 다시 선택할 수 있습니다.

## 개발 실행

프로젝트 루트에서 실행합니다.

```sh
npm ci
npm run dev
```

개발 모드는 `127.0.0.1:5187`의 Vite 서버와 Electron을 함께 시작합니다. 포트가 이미 사용 중이면 먼저 해당 개발 서버를 종료하세요. React 화면 변경은 개발 서버가 반영하며, Electron 메인 프로세스·preload 변경은 개발 앱을 다시 시작해야 합니다.

빌드된 파일로 실행하려면 다음 명령을 사용합니다.

```sh
npm run build
npm start
```

## 기본 사용 흐름

### 1. 작업 폴더 연결

이미 체크아웃한 폴더가 있다면 **기존 폴더 열기**를 선택합니다. 여러 프로젝트를 등록한 뒤 상단 프로젝트 선택 상자에서 전환할 수 있습니다. 프로젝트 목록과 마지막 선택은 다음 실행에도 복원됩니다.

새로 받을 때는 **체크아웃**을 누르고 저장소 URL, 앱에 표시할 프로젝트 이름, 저장할 폴더를 입력합니다. 대상은 새 경로 또는 비어 있는 폴더여야 합니다. 기존 파일이 있는 폴더는 거부합니다.

### 2. 저장소 로그인

저장소가 인증을 요구하면 **저장소 로그인** 창에서 SVN 사용자 이름과 비밀번호를 입력합니다. 앱 회원가입은 필요하지 않습니다. URL에 사용자 이름이나 비밀번호를 포함하지 말고 로그인 창을 사용하세요.

**이 맥에 계정 정보 저장**을 선택하면 Electron `safeStorage`로 비밀번호를 암호화해 앱 데이터에 보관합니다. 선택하지 않으면 현재 앱 실행 동안만 사용하며, 같은 저장소에 저장돼 있던 인증 정보도 제거합니다. 암호화 기능을 사용할 수 없으면 저장 옵션이 비활성화됩니다.

비밀번호는 SVN 프로세스의 명령행 인수 대신 표준 입력으로 전달합니다. 로그인 저장에 실패해도 이미 완료된 SVN 작업은 유지되며, 현재 실행 중에는 계정을 사용할 수 있습니다.

### 3. 이력과 변경 내용 확인

왼쪽에서 커밋을 선택하면 오른쪽에 작성자, 리비전, 날짜, 전체 메시지와 변경 파일이 표시됩니다. 파일을 선택하면 해당 리비전에서 생긴 텍스트 변경을 확인할 수 있습니다.

이력은 한 번에 **50개**씩 불러옵니다. **이전 커밋 더 보기**로 오래된 이력을 추가합니다. 검색 대상은 **현재 불러온 커밋의 메시지·작성자·리비전**이며, 저장소 전체를 서버에서 검색하는 기능은 아닙니다.

### 4. 최신 변경 받기

**업데이트**를 누르면 서버 변경을 현재 작업 폴더에 반영합니다. 완료 화면에서 리비전, 처리한 파일, 작업 기록을 확인할 수 있습니다. 충돌이 생기면 **충돌 확인**으로 이동합니다.

### 5. 선택한 항목 커밋

**커밋**을 누르고 변경 내용을 확인한 뒤 보낼 파일 또는 삭제 폴더를 체크합니다. 메시지를 입력하고 **N개 항목 커밋**을 누르면 선택한 변경을 서버에 반영합니다. 선택하지 않은 수정 파일과 새 파일은 그대로 남습니다.

- 새 파일은 필요한 상위 폴더와 함께 추가합니다. 새 폴더 아래의 다른 미선택 파일까지 함께 올리지 않습니다.
- 로컬에서 삭제해 `누락` 상태가 된 파일을 선택하면 저장소에도 삭제를 반영합니다.
- 신규 폴더는 내부 파일을 펼쳐 보여줍니다. `.svn`, `.git`, `node_modules`, SVN ignore에 해당하는 항목은 제외합니다.
- 삭제·누락된 폴더는 하위 항목을 함께 삭제합니다. 폴더를 누르면 삭제 범위를 확인할 수 있고, 하위 파일을 누르면 삭제 전 내용을 볼 수 있습니다. 커밋 직전에도 삭제 목록을 다시 확인합니다. 목록은 로컬 작업본의 SVN 메타데이터로 조회하며 서버 접속이나 작업 파일 수정 없이 표시합니다.
- 폴더 자체의 신규 추가·속성 변경을 직접 선택해 커밋하는 기능은 지원하지 않습니다. 일부만 체크아웃했거나 다른 SVN 경로로 전환된 폴더는 전체 삭제 범위를 확인할 수 없어 차단합니다.

### 6. 충돌 처리

충돌 파일은 **기본 앱으로 파일 열기** 또는 사용 중인 편집기에서 직접 수정하고 저장합니다. 그다음 **해결로 표시**를 누릅니다. 이 동작은 현재 파일 내용을 유지하며 SVN의 충돌 표시를 해제합니다. 내용을 자동으로 병합하거나 올바른 해결안을 선택해 주지는 않습니다.

작업 폴더에 충돌이 남아 있으면 커밋할 수 없습니다. 파일·폴더 이동이나 삭제 관계가 얽힌 **트리 충돌**은 이 버전에서 해결할 수 없으므로 별도 SVN 도구에서 처리해야 합니다.

## 예제 저장소로 사용해 보기

실제 업무 저장소 없이 독립된 로컬 저장소를 생성할 수 있습니다.

```sh
node scripts/create-demo.mjs work/demo
```

출력되는 `workspace`를 앱의 **기존 폴더 열기**로 선택하세요. 예제에는 커밋 3개, 수정 파일 2개, 한글·공백·`@`가 포함된 새 파일 1개가 있습니다. `peer`는 다른 작업자의 변경을 만들어 볼 수 있는 두 번째 작업 폴더입니다. `repository`가 실제 로컬 SVN 저장소입니다.

생성 스크립트는 대상 디렉터리가 이미 있으면 중단합니다. 다시 만들 때는 다른 새 경로를 지정하세요. 기본 명령 경로는 `/opt/homebrew/bin/svn`과 `/opt/homebrew/bin/svnadmin`이며, 필요하면 `SVN_BINARY`, `SVNADMIN_BINARY` 환경 변수로 바꿀 수 있습니다.

## 검사와 테스트

```sh
npm run typecheck
npm test
```

SVN 서비스와 설정 저장은 0.1.0에서 자동 테스트 15개를 통과했습니다. 0.1.1은 타입 검사와 다음 화면 회귀 검증을 추가로 통과했습니다.

```sh
npm run test:renderer
npm run test:folders
```

이 명령은 실제 SVN 대신 가짜 API를 넣은 별도 Electron 창에서 프로젝트 전환, 늦은 오류 응답, 드래그·키보드 너비 조절, 저장값 복원, 창 크기 변경을 검증합니다. 실제 작업 폴더나 SVN 서버를 사용하지 않습니다.

테스트는 임시 저장소와 작업 폴더를 만들어 체크아웃·이력 페이지·추가/복사/삭제 diff·선택 커밋·한글 및 특수문자 경로·ignore·업데이트·충돌 해결·경로 제한·취소·중복 실행 방지를 검사합니다. 인증 테스트는 임의의 빈 localhost 포트에서 `svnserve`를 실행해 인증 실패 후 재시도를 확인합니다. 종료할 때 임시 데이터와 서버를 정리합니다.

설정 테스트는 프로젝트 선택과 재시작 복원, 암호문 저장, 세션 전용 계정, 저장 불가 시 동작을 검사합니다. 이 테스트의 암호화는 mock이며, 실제 macOS 암호화 저장소의 동작을 대신 검증한 것은 아닙니다.

테스트 실행에는 `svn`, `svnadmin`, `svnserve`와 localhost 통신 권한이 필요합니다. 명령 경로가 다르면 `SVN_BINARY`와 `SVNADMIN_BINARY`를 설정하세요. `svnserve`는 지정한 `svnadmin`과 같은 디렉터리에서 찾습니다. 실제 업무 저장소에는 테스트 데이터를 만들지 않습니다.

## macOS 앱 패키징

```sh
npm run pack:mac
npm run dist:mac
```

`pack:mac`은 앱 번들, `dist:mac`은 DMG를 `release`에 생성합니다. **Apple Silicon용 0.1.3 DMG를 제공합니다.** 설치 파일 체크섬과 패키지에 포함된 코드가 검증한 빌드와 일치하는지 확인했습니다. Apple Developer 서명과 공증은 구성하지 않았습니다.

- `release/SVN Workspace-0.1.3-arm64.dmg`를 열고 앱을 Applications로 복사해 사용할 수 있습니다.
- 생성된 앱은 `release/mac-arm64/SVN Workspace.app`에서도 바로 실행할 수 있습니다.
- macOS에서 개발자 확인 안내가 나오면 앱의 출처를 확인한 뒤 시스템 설정의 개인정보 보호 및 보안에서 해당 앱의 실행을 허용할 수 있습니다. 시스템 전체 보안 설정을 끌 필요는 없습니다.
- 초기 0.1.0에서는 앱 번들을 직접 실행해 시작 화면과 SVN 자동 감지를 확인했습니다. 다른 Mac으로 내려받아 설치하는 과정과 Gatekeeper 승인은 검증하지 않았습니다.

초기 0.1.0의 실제 Electron 화면에서 독립 예제 저장소의 체크아웃, 커밋 목록·검색·변경 비교, 커밋 작성 화면을 확인했습니다. 1440×900 화면과 1024×700 레이아웃에서 가로 넘침을 확인했으며 앱 오류는 관찰되지 않았습니다. 커밋·업데이트·인증 재시도는 별도 서비스 통합 테스트 결과이며, 모든 작업을 GUI에서 끝까지 재검증했다는 의미는 아닙니다. 기존 업무 SVN 저장소와 작업 파일에는 접근하거나 변경하지 않았습니다.

최신 삭제 화면 예시는 `screenshots/11-folder-deletion.png`, `screenshots/12-folder-deletion-review.png`, `screenshots/13-folder-deletion-compact.png`에 있습니다. 화면 회귀 검증용 가상 데이터입니다.

## 현재 제약

- 이 앱은 실제 SVN 작업을 실행합니다. 취소는 실행 중인 프로세스를 중단하며, **이미 적용된 파일 변경이나 완료된 커밋을 자동으로 되돌리지 않습니다.** 중단 후 현재 파일 상태를 확인하세요. 부분 체크아웃이 남으면 별도 SVN 도구로 복구하거나 새로운 빈 경로를 지정해야 합니다.
- 한 번에 하나의 변경 작업만 실행합니다. 작업 중 프로젝트 전환이나 중복 커밋·업데이트는 제한됩니다.
- 별도의 revert, cleanup, branch/tag, merge, 삭제 외의 폴더 단위 커밋, 트리 충돌 해결 UI는 없습니다.
- diff는 텍스트 중심입니다. 새 파일 미리보기는 UTF-8·1 MB 이하이며 바이너리 비교는 지원하지 않습니다. 신규 폴더 탐색은 깊이 20, 탐색 항목 3,000개를 제한으로 둡니다.
- 대규모 저장소, HTTPS 인증서 처리, SSH 저장소는 아직 실제 환경에서 검증하지 않았습니다. 인증서를 자동으로 신뢰하거나 SSH 키를 관리하는 UI는 없습니다.
- 앱 설정과 암호화된 계정 정보는 Electron의 사용자 데이터 디렉터리에 저장합니다. 개발·테스트 데이터를 분리할 때는 앱 실행 전에 `SVN_WORKSPACE_DATA_DIR`을 별도 경로로 지정할 수 있습니다.

| `src/main/svn-service.ts` | SVN 실행, XML 해석, 경로 검증 |
