# 사용 가이드

SVN Workspace에서 작업 폴더를 연결하고 이력 확인, 업데이트, 선택 항목 커밋을 진행하는 방법입니다.

[프로젝트 소개](../README.md) · [개발 가이드](DEVELOPMENT.md) · [버전별 변경 내역](../CHANGELOG.md)

## 1. SVN 실행 파일 연결

macOS에 Subversion CLI가 설치되어 있어야 합니다. 앱에는 SVN 실행 파일이 포함되어 있지 않습니다.

저장된 실행 파일 경로가 없으면 `/opt/homebrew/bin/svn`, `/usr/local/bin/svn`, `/usr/bin/svn`, `PATH` 순서로 찾습니다. 찾지 못하거나 저장된 경로가 더 이상 유효하지 않으면 시작 화면의 **SVN 실행 파일 선택**에서 직접 지정하세요.

## 2. 작업 폴더 연결

### 기존 작업 폴더 열기

**기존 폴더 열기**를 선택하고 이미 체크아웃한 SVN 작업 폴더를 지정합니다. 여러 프로젝트를 등록할 수 있으며, 상단 선택 상자에서 전환합니다. 프로젝트 목록과 마지막 선택은 다음 실행에도 복원됩니다.

### 새로 체크아웃

1. **체크아웃**을 누릅니다.
2. 저장소 URL, 앱에 표시할 프로젝트 이름, 저장할 폴더를 입력합니다.
3. **체크아웃**으로 시작합니다. 인증이 필요하면 로그인 창이 표시됩니다.

선택한 폴더가 최종 체크아웃 위치입니다. 하위 폴더 이름을 자동으로 덧붙이지 않습니다. 폴더 선택 창에서 새 폴더를 만들거나 빈 폴더를 선택할 수 있고, 입력란에 새 경로를 직접 지정할 수도 있습니다. 경로는 절대 경로 또는 `~/`로 시작하는 경로를 사용하세요.

대상은 새 경로 또는 비어 있는 폴더여야 합니다. 파일이 있는 폴더는 거부합니다. 저장소 URL에 사용자 이름이나 비밀번호를 포함하지 마세요.

## 3. 저장소 로그인

**저장소 로그인** 창에서 해당 SVN 저장소의 사용자 이름과 비밀번호를 입력합니다. 별도의 앱 계정은 필요하지 않습니다.

- **이 맥에 계정 정보 저장**을 선택하면 Electron `safeStorage`로 비밀번호를 암호화해 앱 데이터에 보관합니다.
- 선택하지 않으면 현재 앱 실행 동안만 사용하며, 같은 저장소에 저장돼 있던 인증 정보도 제거합니다.
- 암호화 저장소를 사용할 수 없으면 저장 옵션이 비활성화됩니다.
- 비밀번호는 SVN 프로세스의 명령행 인수 대신 표준 입력으로 전달합니다.

로그인 정보 저장에 실패하더라도 이미 완료된 SVN 작업은 유지됩니다. 이때 계정은 현재 실행 중에만 사용하므로 다음 실행에서 다시 로그인해야 합니다.

## 4. 커밋 이력과 변경 내용 확인

왼쪽 커밋 목록에서 항목을 선택하면 오른쪽에 작성자, 리비전, 날짜, 전체 메시지와 변경 파일이 표시됩니다. 파일을 선택하면 해당 리비전의 텍스트 변경을 확인할 수 있습니다.

- 이력은 한 번에 **50개**씩 불러옵니다. **이전 커밋 더 보기**로 오래된 이력을 추가합니다.
- 검색은 **현재 불러온 이력의 메시지·작성자·리비전**을 대상으로 합니다. 저장소 전체를 서버에서 검색하지는 않습니다.
- 커밋 목록 오른쪽 경계를 드래그해 너비를 조절합니다. 경계에 초점을 둔 뒤 방향키로도 조절할 수 있으며, 너비는 다음 실행에도 유지됩니다.

## 5. 업데이트와 커밋

### 최신 변경 받기

**업데이트**를 누르면 서버 변경을 현재 작업 폴더에 반영합니다. 완료 화면에서 리비전, 처리한 파일, 작업 기록을 확인할 수 있습니다. 충돌이 생기면 **충돌 확인**으로 이동합니다.

### 선택한 항목 커밋

1. **커밋**을 눌러 내 변경 사항을 확인합니다.
2. 파일을 선택해 변경 내용을 확인하고, 보낼 항목의 체크 상자를 선택합니다.
3. 커밋 메시지를 입력한 뒤 **N개 항목 커밋**을 누릅니다.

선택하지 않은 수정 파일과 새 파일은 커밋 대상에서 제외됩니다. 새 파일에 필요한 상위 폴더는 함께 추가하지만, 그 폴더 아래의 미선택 파일까지 추가하지는 않습니다. 신규 폴더를 펼칠 때는 `.svn`, `.git`, `node_modules`, SVN ignore에 해당하는 항목을 제외합니다.

로컬에서 삭제해 `누락` 상태가 된 파일을 선택하면 저장소에도 삭제를 반영합니다.

### 폴더 삭제 커밋

삭제되었거나 로컬에서 통째로 지워 누락된 폴더를 선택할 수 있습니다. 폴더를 누르면 함께 삭제될 하위 파일·폴더와 개수가 표시됩니다. 하위 파일을 누르면 삭제 전 내용을 확인할 수 있습니다.

폴더가 포함된 커밋은 최신 삭제 목록을 조회한 뒤 **폴더 삭제 범위 확인 → 삭제 포함 커밋**으로 진행합니다. 조회에 실패하면 커밋하지 않습니다. 하위 삭제는 상위 폴더와 중복 선택되지 않습니다.

삭제 목록은 로컬 SVN 메타데이터로 조회합니다. 일부만 체크아웃했거나 하위 경로가 다른 SVN 경로로 전환된 폴더는 전체 삭제 범위를 확인할 수 없어 차단합니다.

## 6. 충돌 처리

충돌 파일은 **기본 앱으로 파일 열기** 또는 사용 중인 편집기에서 직접 수정하고 저장합니다. 그다음 **해결로 표시**를 누릅니다. 이 동작은 현재 파일 내용을 유지하며 SVN의 충돌 표시를 해제합니다. 자동으로 병합하거나 해결안을 선택해 주지는 않습니다.

작업 폴더에 충돌이 남아 있으면 커밋할 수 없습니다. 파일·폴더 이동이나 삭제 관계가 얽힌 **트리 충돌**은 별도 SVN 도구에서 처리해야 합니다.

## 7. 프로젝트 관리

| 기능 | 사용 방법과 동작 |
| --- | --- |
| VS Code로 열기 | 상단 **VS Code**로 실제 프로젝트 폴더를 새 창에서 엽니다. VS Code 설치 또는 `code` 명령 등록이 필요합니다. |
| 별칭 변경 | **⋯ → 별칭 변경**에서 앱에 표시할 이름을 저장합니다. 폴더명과 SVN 경로는 유지됩니다. **폴더명으로 초기화 → 저장**으로 기본 이름을 복원합니다. |
| 목록에서 제거 | **⋯ → 목록에서 제거**로 앱에 저장된 프로젝트 등록을 제거합니다. 실제 폴더·파일·SVN 저장소·로그인 정보는 유지됩니다. 폴더가 이미 없어도 제거할 수 있습니다. |

선택 중인 프로젝트를 제거하면 남은 첫 프로젝트로 전환합니다. 마지막 항목을 제거하면 빈 목록으로 돌아갑니다. SVN 변경 작업 중에는 프로젝트를 전환하거나 목록에서 제거할 수 없습니다.

## 현재 지원 범위

- **작업 취소는 롤백이 아닙니다.** 실행 중인 프로세스를 중단해도 이미 적용된 파일 변경이나 완료된 커밋은 되돌리지 않습니다. 취소 후 현재 파일 상태를 확인하세요. 부분 체크아웃이 남으면 별도 SVN 도구로 복구하거나 새로운 빈 경로를 사용해야 합니다.
- 한 번에 하나의 변경 작업만 실행합니다.
- revert, cleanup, branch/tag, merge, 삭제 외의 폴더 자체 변경 커밋, 트리 충돌 해결 UI는 제공하지 않습니다.
- diff는 텍스트 중심입니다. 새 파일 미리보기는 UTF-8·1 MB 이하이며 바이너리 비교는 지원하지 않습니다. 신규 폴더 탐색은 깊이 20, 탐색 항목 3,000개로 제한합니다.
- 대규모 저장소, HTTPS 인증서 처리, SSH 저장소는 실제 환경에서 검증하지 않았습니다. 인증서를 자동 신뢰하거나 SSH 키를 관리하는 UI는 없습니다.
